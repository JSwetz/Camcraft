# M4.1 — crate split design notes

Provenance: our own architecture notes for ROADMAP M4.1 ("separate the
code into crates"), derived from the in-crate dependency map below
(extracted from `use crate::` / `use super::` references, 2026-10-23,
HEAD 138f568). No external design source.

## The measured shape (app crate, 29.3 kLOC)

Module → modules it references (top-level view; commands/* collapsed to
their targets):

| seed area | modules | LOC | depends on (outside itself) |
|---|---|---|---|
| geometry | geometry/*, geo2d | ~3.2k | units (lattice only) |
| motion model | cl | 0.5k | geometry, geo2d, units |
| generators | machining2d/3d, finishing3d, drilling, rest | ~6.1k | cl, geo2d, geometry, tools, stock_sim |
| sim/verify | sim, stock_sim, solid_rest, verify | ~3.6k | cl, geometry, geo2d, model, setup, stock, tools, machining3d |
| tools | tools, tool_list | 0.7k | verify (tools), cl/geo (list) |
| post engine | post/*, machine | ~2.3k | cl, cnc; machine: geometry |
| ecs glue | schema, world, model, setup, stock, fixture, pick | ~2.2k | everything shallow |
| orchestration | operation, posting, setup_sheet, project, commands/* | ~7.5k | everything |

Two knots to untie BEFORE any `Cargo.toml` changes:

1. **schema ↔ domain cycles are only about plain types.** schema imports
   `operation::{SrcRef, OpParams, GenStamp}`, `verify::Warning`,
   `tools::Tool`, `stock::StockShape`, `machine::Machine`, `units::Unit`,
   `cl::Toolpath`, `geometry::{Point3, Triangle}`. The component wrappers
   themselves stay in schema (AGENTS.md law holds); the PLAIN types must
   move to homes that import no schema.
2. **The generator ↔ verifier cycle.** `verify → machining3d → stock_sim`
   and `stock_sim` is generator-adjacent; break it by having verify take
   generated paths as data (it already mostly does) and moving the
   `machining3d` calls behind a trait or into `rest`-style helpers on the
   generator side.

## Target crates (workspace, new names `camcraft-*` — M4.3 law: new
## identifiers do not spread the old brand; existing hsmworks-* crates
## keep their names until M4.3 renames them)

```
camcraft-geometry   geometry/*, geo2d, units::Unit (enum only)    deps: none
camcraft-cl         cl (motion model, lattice, intermediate fmt)  deps: geometry
camcraft-tools      tools (catalog types only)                    deps: geometry
camcraft-post       post/*, machine (parse+mirror)                deps: cl, geometry
camcraft-motion     machining2d/3d, finishing3d, drilling, rest   deps: cl, geometry, tools, sim (one-way)
camcraft-sim        sim, stock_sim, solid_rest, verify            deps: cl, geometry, tools, model-iface
hsmworks-app        schema, world, model, setup, stock, fixture,
                    pick, operation, posting, setup_sheet,
                    project, commands/*, units glue, bins        deps: all above
hsmworks-ui         unchanged                                     deps: app
```

`sim` needing `model/setup` (entities) is the deepest knot: the fix is an
interface, not a dependency — sim consumes `(facets, stock, tool)` tuples
the app hands it; UI-facing entity traversal stays in app.

## Ladder (each rung is a gated commit; tree builds green throughout)

- **R0 — type relocations inside app.** Move plain data types to their
  crate-future homes; delete the reverse imports (schema keeps only
  wrappers). Gate: full debug ladder + clippy (no behavior change; goldens
  byte-identical).
- **R1 — camcraft-geometry.** First extraction; app re-exports
  `geometry`/`geo2d` so UI compiles untouched. Move its tests (geo2d,
  slice, import? import needs truck → import stays in app; the pure mesh
  ops move).
- **R2 — camcraft-cl + camcraft-tools.** cl is nearly standalone (its
  golden CLFile tests move with it). tools: split catalog types (crate)
  from entity glue (app `commands/tool`, `tool_list` sheet rendering).
- **R3 — camcraft-post.** post/* is pure Value-in/program-out; machine.rs
  parse/mirror joins; `posting.rs` (ECS glue) stays in app. post.exe's bin
  moves to the post crate (the product binary this roadmap names).
- **R4 — camcraft-sim + camcraft-motion.** Largest edge surgery; break
  verify→machining3d and stock_sim↔generators per the knot notes. finish3d/
  stock_sim/sim/verify test suites move to their crates (M4.4 lane law
  travels with them: `#[ignore]` markers + Gate-map headers keep their
  meaning; gate binaries gain `-p` per crate).
- **R5 — cleanup.** 400-line rule sweep during the moves (operation.rs
  3.8k and project/mod.rs 2.3k split along their existing section seams);
  `cargo check -p` per touched crate replaces the two-crate rule in
  AGENTS.md; graphify full rebuild (many files moved).

## Laws that ride along

- Coverage law: `#[test]` count before == after, per rung (M4.4).
- Goldens: `tests/golden/` paths referenced by moved suites resolve via
  the same `CARGO_MANIFEST_DIR` discipline; 13 .nc goldens stay
  byte-identical across R0–R5.
- Everything-is-a-command: commands/* stay in app (they touch worlds);
  generators get no new ECS writes in the move.
- CI ladder grows `-p` flags per rung; the release-heavy lane follows the
  ignore markers to their new crates.

## R0 landed (2026-10-23) — what the map looked like up close

Measured while executing R0, a fifth relocation the survey missed:
`schema::WCS_SLOTS` is a pure const that `operation`'s height code reads
by path — it moved to `operation::types` (schema keeps a `pub use`, the
commands/UI paths unchanged). Confirmed clean already: `stock`,
`verify`, `cl`, `geometry` import NO schema, so their schema edges are
one-way and need no surgery. Where the pieces live now:

- `geometry/units.rs` — `Unit` enum + `MM_PER_INCH` (the future
  camcraft-geometry home); `units.rs` keeps the flecs singleton glue and
  the display formatters and re-exports both.
- `machine/def.rs` (types, 308 ln) + `machine/parse.rs` (the `.mch`
  reader, 255 ln) + `machine/mod.rs` (singleton glue + the program
  checker, 251 ln) — also a 400-line-rule fix: machine.rs was 784.
- `operation/types.rs` (808 ln): `SrcRef`, `GeoSel`, `FeatureSel`,
  `OpType`, `HeightReference`, `Height`, `OpParams`, `GenStamp`,
  `OpStatus`, `WCS_SLOTS` — zero world references. The world methods of
  the same types (`Height::z`/`z_for`, `OpParams::stamp_with`,
  `resolve_height`, `current_stamp`...) stay in `operation/mod.rs` as
  separate impl blocks.
- `tools.rs` — `ToolGeom` moved here from `verify` (it describes a
  tool); `verify` re-exports it so every `verify::ToolGeom` path keeps
  compiling. The `tools ↔ verify` edge is now one-way verify→tools.

## Decisions to log in RECOMMENDED.md at close-out

- New crates named `camcraft-*` while old ones wait for M4.3.
- Heights/offsets (roadmap's 4th named area) has no module today — the

  seam, else it's recorded as already-separated.
- post.exe binary moving to camcraft-post (it only needs the post crate).

## R1 landed (2026-10-23) — camcraft-geometry out first

`crates/geometry` (package `camcraft-geometry`) holds `geometry/*`
minus `import/` + `geo2d.rs`, and the `geo2d`/`slice` test suites.
The tree mirrors the old app paths (`camcraft_geometry::geometry`,
`::geo2d`) — every moved file compiled untouched, which is the whole
point of cutting on the R0 seams. App keeps `src/geometry/mod.rs` as a
shim (`pub use camcraft_geometry::geometry::*; pub mod import;`) so all
`crate::geometry::…`/`crate::geo2d::…` paths — 18 UI files included —
hold. Deviations from the table above, recorded:

- deps are `clipper2-rust` + `thiserror`, not "none": geo2d's
  offsets/booleans ride clipper2 and the error enums derive thiserror.
  Neither touches ECS — the boundary law (no flecs, no schema) holds.
- truck stays out: `geometry/import/` (STL/OBJ/STEP) lives in app, so
  `geometry::load_model`/`ImportError` resolve through the shim; the
  `import` test suite (20) stays in app with them.
- the `feature` integration suite (18) stays in app — it drives
  `model`/`world` fixtures (decompose), which the crate must not know.
  Its `hsmworks_app::geometry::feature::` paths needed no edit.
- CI ladder grew `-p camcraft-geometry` (test step + clippy); unit
  counts moved exactly: app lib 98→78, crate lib 20, crate suites
  geo2d 15 + slice 9 — coverage law held at 785 total.

## R2 landed (2026-10-23) — camcraft-cl + camcraft-tools

`crates/cl` and `crates/tools` hold `cl.rs` and `tools.rs` verbatim
(module tree mirrored again: `camcraft_cl::cl` re-exports the geometry
crate's `geometry`/`geo2d` names so the file's `crate::geometry::…`
paths never changed; app: `pub use camcraft_cl::cl` /
`camcraft_tools::tools`). Deviations from the table:

- **camcraft-tools has NO deps** - the R0 audit already proved
  tools.rs imports nothing, and that still holds after the move (the
  table said "deps: geometry"; the catalog types turn out to need
  neither points nor units).
- **the display formatters moved early**: cl.rs's one `crate::units`
  read (`feed`) is a pure Unit function, so it belongs with the enum,
  not with the flecs glue. `geometry/units.rs` now owns `to_display/
  from_display/len/len_signed/feed/area`; `units.rs` keeps the
  singleton glue and re-exports everything - every `crate::units::…`
  path in app and UI holds. This is what let cl leave with a
  geometry-only edge, exactly as the table wanted.
- `cl::lattice` was `pub(crate)` (a cross-module law of the old app);
  it is now public cl-crate API - the generators quantize through it,
  so it IS part of the CL contract.
- `golden_cl` (20) stays in app like `feature`/`import` before it: it
  GENERATES via machining2d fixtures (tests/common), which the motion
  crate must not know. cl's own 4 lattice/digest tests + tools' 5
  travel as libtests in their crates; app lib 78→69, crate libs 4+5.
- The design's "entity glue (commands/tool, tool_list) splits off"
  half was already true at R0 - those files never lived in tools.rs.

## R3 landed (2026-10-23) — camcraft-post, and post.exe comes home

`crates/post` (package `camcraft-post`) holds `post/*` verbatim, the
`.mch` GRAMMAR (`machine/def.rs` types + `machine/parse.rs` reader —
"machine (parse+mirror)" from the target table: the mirror in
`post::machine` restates those types, one grammar one home), and the
`post.exe` bin — the product binary the roadmap names, built from this
crate now (`cargo build -p camcraft-post`; release.yml gained the `-p`).
App's `machine/mod.rs` keeps what touches the world (singleton glue +
program checker) and re-exports the grammar, so every
`crate::machine::…`/`crate::post::…` path in app and UI holds.

- deps: cl + geometry (re-exported at the crate root so moved paths
  held verbatim), boa_engine (left app entirely with js.rs — app no
  longer links a JS engine), thiserror, serde/serde_json.
- `def::Machine::axis/feed_ceiling` were `pub(super)` inside app's
  machine dir; they cross the checker's seam now, so they are public
  camcraft-post API.
- `post_engine` (17) moved with the engine; its reads of the `.cl`
  goldens point at app's fixture dir (`../app/tests/golden`) - the
  goldens are generator output, golden_cl still owns writing them
  (CARGO_MANIFEST_DIR discipline, one hop across, fixtures untouched).
- fanuc_post/conformance stay in app: they drive posting/world.
- Coverage law: 785 == 785 (app lib 69; engine tests live in the post
  crate binary now). All 39 binaries + a post.exe CLI smoke
  (--version stamps 0.3.0; drill_plate.cl posts) green; clippy -D
  warnings clean across six packages.

## R4 landed

camcraft-sim (fixture predicates, sim, solid_rest, the stock_sim
engine, verify) and camcraft-motion (machining2d/3d, finishing3d,
drilling) joined the workspace; stock.rs sank to geometry (it is
mesh-domain data: box/cylinder/none + transforms, no flecs).

- **The knot dissolved, it was not cut.** The design note feared a
  model/setup interface; the engines already spoke in tuples - only
  the world-facing halves knew it. What stayed in app is exactly the
  entity-walking half of `stock_sim` (build the stock solid from
  `Stock`/`Setup`, drive a document through the sim) and the
  entity/glue half of `fixture` (`boxes_for`, the table from `.mch`);
  both re-export their crate whole, so every app and UI path holds.
- **The one real edge - verify -> machining3d::material_above - is
  now `geometry::slice::material_above`.** The nudge-probe law is a
  mesh law; it lives at the mesh layer. `machining3d::material_above`
  stays as the generator's GenError-typed wrapper, and the verifier's
  island cache reads the same function: one law, three readers, zero
  back-edges. motion -> sim remains the only cross-seam dependency
  (machining3d's dexel rest queries).
- **Deviation, recorded:** `rest.rs` is remachining ORCHESTRATION
  (who counts as prior, by setup traversal) - it is app glue, not a
  generator, so it stays; the design table's "rest in motion" was
  wrong. `sim::Traverse` moved to sim with stock_sim (it consumes
  moves + rates, no world).
- Tree-mirroring as before: `crate::geometry::...`, `crate::cl::...`,
  `crate::stock_sim::...` paths compile verbatim across the boundary
  via crate-root aliases (`pub use camcraft_sim::stock_sim` in motion
  is the one alias that points at a sibling seam, not a foundation).
- Coverage law: 785 == 785 (app lib 17 - the moved inline suites rode
  their files: sim lib 16, motion lib 27; suites: stock_sim to the sim
  crate, machining2d/3d + finish3d to motion). All 42 wave binaries +
  the release-lane ignores (28 in motion's finish3d, 2 in app's
  verify) + clippy -D warnings over eight packages green; the 13 .nc
  goldens byte-identical; headless run rc=0.

## R5 landed — the app-internal seams

No crates moved; the two remaining app monoliths split along their
section seams (`operation/mod.rs` ~2996 -> 11 files, `project/mod.rs`
~2350 -> 8 files), which is what the ROADMAP's R5 rung asked for.

- `operation`: heights / params (impl blocks only) / stamp / material /
  selection / picks / stitch / generate + the old inline `mod tests` as
  `tests.rs`. The public surface is unchanged: `pub` items kept `pub`
  and re-exported with `pub use x::*;`; section-private helpers became
  `pub(super)` - visible exactly where they were before (inside the
  `operation` subtree), so no new API and no lost API. `types.rs`
  stays the component/type registry; `mod params;` carries no glob
  (impls need no re-export).
- `project`: file / params / params_impl / entity / wire / apply /
  validate. `mod.rs` keeps the docs + the single import block; regions
  are `use super::*;` only, so every `use` line stays exactly one -
  trimming per-file import lists was the alternative and it drifts.
  PROJECT_VERSION (23) rode to `file.rs`; serde DTO conversions
  promoted `pub(super)` where apply/validate consume wire's types.
- Mechanics note: a split-out file for a `mod x;` declaration holds the
  module's CONTENTS, not another `mod x {}` wrapper - the tests file
  taught that the hard way (double nesting = the tests' `use super::*`
  saw an empty scope).
- Gate: check app+ui clean, clippy -D warnings over app clean, 29/29
  wave binaries green, release-lane ignores 2/2 (app verify envelope
  verdicts), coverage 785 == 785, `tests/` untouched in git status
  (goldens byte-identical).
- Residual 400-line debt inside the new files (generate 481,
  params_impl 499, params 463, selection 416, stitch 413, types 808 -
  the last predates this rung) -> RECOMMENDED.md ledger, to be paid
  per-file the next time each is touched, not in a dedicated sweep.

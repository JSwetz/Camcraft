# M4.1 — crate split design notes

Provenance: our own architecture notes for ROADMAP M4.1 ("separate the
code into crates"), derived from the in-crate dependency map below
(extracted from `use crate::` / `use super::` references, 2026-10-23,
HEAD 138f568). No external design source.

## The measured shape (app crate, 29.3 kLOC)

Module → modules it references (top-level view; commands/* collapsed to
their targets):

| seed area | modules | LOC | depends on (outside itself) |
|---|---|---|---|
| geometry | geometry/*, geo2d | ~3.2k | units (lattice only) |
| motion model | cl | 0.5k | geometry, geo2d, units |
| generators | machining2d/3d, finishing3d, drilling, rest | ~6.1k | cl, geo2d, geometry, tools, stock_sim |
| sim/verify | sim, stock_sim, solid_rest, verify | ~3.6k | cl, geometry, geo2d, model, setup, stock, tools, machining3d |
| tools | tools, tool_list | 0.7k | verify (tools), cl/geo (list) |
| post engine | post/*, machine | ~2.3k | cl, cnc; machine: geometry |
| ecs glue | schema, world, model, setup, stock, fixture, pick | ~2.2k | everything shallow |
| orchestration | operation, posting, setup_sheet, project, commands/* | ~7.5k | everything |

Two knots to untie BEFORE any `Cargo.toml` changes:

1. **schema ↔ domain cycles are only about plain types.** schema imports
   `operation::{SrcRef, OpParams, GenStamp}`, `verify::Warning`,
   `tools::Tool`, `stock::StockShape`, `machine::Machine`, `units::Unit`,
   `cl::Toolpath`, `geometry::{Point3, Triangle}`. The component wrappers
   themselves stay in schema (AGENTS.md law holds); the PLAIN types must
   move to homes that import no schema.
2. **The generator ↔ verifier cycle.** `verify → machining3d → stock_sim`
   and `stock_sim` is generator-adjacent; break it by having verify take
   generated paths as data (it already mostly does) and moving the
   `machining3d` calls behind a trait or into `rest`-style helpers on the
   generator side.

## Target crates (workspace, new names `camcraft-*` — M4.3 law: new
## identifiers do not spread the old brand; existing hsmworks-* crates
## keep their names until M4.3 renames them)

```
camcraft-geometry   geometry/*, geo2d, units::Unit (enum only)    deps: none
camcraft-cl         cl (motion model, lattice, intermediate fmt)  deps: geometry
camcraft-tools      tools (catalog types only)                    deps: geometry
camcraft-post       post/*, machine (parse+mirror)                deps: cl, geometry
camcraft-motion     machining2d/3d, finishing3d, drilling, rest   deps: cl, geometry, tools, sim (one-way)
camcraft-sim        sim, stock_sim, solid_rest, verify            deps: cl, geometry, tools, model-iface
hsmworks-app        schema, world, model, setup, stock, fixture,
                    pick, operation, posting, setup_sheet,
                    project, commands/*, units glue, bins        deps: all above
hsmworks-ui         unchanged                                     deps: app
```

`sim` needing `model/setup` (entities) is the deepest knot: the fix is an
interface, not a dependency — sim consumes `(facets, stock, tool)` tuples
the app hands it; UI-facing entity traversal stays in app.

## Ladder (each rung is a gated commit; tree builds green throughout)

- **R0 — type relocations inside app.** Move plain data types to their
  crate-future homes; delete the reverse imports (schema keeps only
  wrappers). Gate: full debug ladder + clippy (no behavior change; goldens
  byte-identical).
- **R1 — camcraft-geometry.** First extraction; app re-exports
  `geometry`/`geo2d` so UI compiles untouched. Move its tests (geo2d,
  slice, import? import needs truck → import stays in app; the pure mesh
  ops move).
- **R2 — camcraft-cl + camcraft-tools.** cl is nearly standalone (its
  golden CLFile tests move with it). tools: split catalog types (crate)
  from entity glue (app `commands/tool`, `tool_list` sheet rendering).
- **R3 — camcraft-post.** post/* is pure Value-in/program-out; machine.rs
  parse/mirror joins; `posting.rs` (ECS glue) stays in app. post.exe's bin
  moves to the post crate (the product binary this roadmap names).
- **R4 — camcraft-sim + camcraft-motion.** Largest edge surgery; break
  verify→machining3d and stock_sim↔generators per the knot notes. finish3d/
  stock_sim/sim/verify test suites move to their crates (M4.4 lane law
  travels with them: `#[ignore]` markers + Gate-map headers keep their
  meaning; gate binaries gain `-p` per crate).
- **R5 — cleanup.** 400-line rule sweep during the moves (operation.rs
  3.8k and project/mod.rs 2.3k split along their existing section seams);
  `cargo check -p` per touched crate replaces the two-crate rule in
  AGENTS.md; graphify full rebuild (many files moved).

## Laws that ride along

- Coverage law: `#[test]` count before == after, per rung (M4.4).
- Goldens: `tests/golden/` paths referenced by moved suites resolve via
  the same `CARGO_MANIFEST_DIR` discipline; 13 .nc goldens stay
  byte-identical across R0–R5.
- Everything-is-a-command: commands/* stay in app (they touch worlds);
  generators get no new ECS writes in the move.
- CI ladder grows `-p` flags per rung; the release-heavy lane follows the
  ignore markers to their new crates.
